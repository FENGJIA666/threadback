From a pause to a next step.

A small map of how Threadback keeps a handoff and carries it forward.

Write a handoffValidate the fieldsSave in this browserResume and record progress

1. The form

app/src/app.js → formModal() collects the goal, confirmed facts, open questions, one next action, and a useful link. It uses validateHandoff() before saving.

2. A safe save

app/src/app.js → persist() validates the entire backup shape and writes to localStorage before updating the visible list. If writing fails, the form remains open with its contents intact.

Why the order matters

Showing success first would risk telling someone their work is saved when the browser has rejected it. The write is the point at which the UI can truthfully confirm persistence.

3. The next handoff

app/src/core.js → completeStep() returns a new object, appends the completed action and its reported result to history, and records a new next action. Open questions are not automatically promoted to confirmed facts.

Try tracing one action

Complete the repair café example, then inspect Earlier handoffs. Follow the action from completeModal() to completeStep() to persist(). The example inventory contains 12 complete kits. A result can record that observation; the next move can use it.

4. Verify the boundary

tests/core.test.mjs checks data and state transitions. tests/browser.spec.mjs exercises the visible flow in a browser, including refresh, import, and storage errors.

A reusable practice: define the visible result and the failure state before implementing an operation that saves user work.
